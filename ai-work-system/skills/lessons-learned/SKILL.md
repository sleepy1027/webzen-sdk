# 피드백을 시스템에 반영하기

AI 업무 시스템은 처음부터 완벽하지 않다. 똑똑해지는 건 **고친 내용이 파일에 남을 때**뿐이다.

## 언제
- 사용자가 결과물을 수정하거나 같은 지적을 두 번 이상 할 때
- 평가 테스트에서 같은 실패가 반복될 때
- 작업 중 "이건 다음에도 알아야 할 사실"을 발견했을 때 (사내 규칙, 예외, 용어)

## 절차
1. **사실로 정리**: 무엇이 틀렸고, 올바른 것은 무엇이며, 왜인지 한 줄씩.
2. **일반화**: 이번 건에만 해당하는가, 같은 유형 전체에 해당하는가? 일반 규칙으로 바꾼다.
   - 나쁜 예: "3월 보고서에서 매출을 굵게 하지 마"
   - 좋은 예: "보고서에서 강조는 결론 문장 1개에만 쓴다 (여러 개면 핵심이 안 보여서)"
3. **어디에 넣을지 결정**
   - 특정 업무의 절차/기준 → 그 업무의 `SKILL.md` (판단 기준 또는 하지 말 것)
   - 모든 업무에 공통인 선호 → `about-me.md` / `CLAUDE.md`
   - 아직 확신 없는 관찰 → `LESSONS.md` (아래 형식)에 쌓아두고 2회 이상 반복되면 승격
4. **반영 전 사용자에게 보여준다**: 바꿀 파일과 추가할 문장을 diff로 제시하고 승인받는다. 파일을 직접 쓸 수 없는 환경(claude.ai 채팅)이면 붙여넣을 문구를 준다.
5. 기존 규칙과 충돌하면 오래된 것을 지우거나 고친다. 규칙을 쌓기만 하면 서로 모순된다.

## LESSONS.md 형식
```
## YYYY-MM-DD <짧은 제목>
- 상황:
- 틀린 것 → 올바른 것:
- 이유:
- 적용 범위: <스킬명 | 전체>
- 반복 횟수: 1
```
