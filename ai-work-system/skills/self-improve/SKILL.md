# 자가 점검·업데이트

시스템이 스스로 나아지는 경로는 두 가지다.
- **개선 제안**: 쓰면서 드러난 문제를 찾아 스킬·지침 수정안을 만든다.
- **자가 업데이트**: 승인된 수정안을 파일에 반영하고 버전·기록을 남긴다. 원본 저장소에 새 버전이 있으면 받아온다.

## 먼저 읽을 것
1. `INSTRUCTIONS.md` — 사용자 지시사항. 개선안은 이것과 충돌하면 안 된다.
2. `LESSONS.md` — 쌓인 피드백 (없으면 건너뜀)
3. `CHANGELOG.md`, `VERSION`
4. 점검 대상 스킬/에이전트 파일

## A. 개선 제안 (기본 동작 — 파일은 바꾸지 않는다)
점검 항목
- [ ] LESSONS.md에서 2회 이상 반복된 항목 → 규칙으로 승격할 후보
- [ ] 스킬 `description`이 실제 요청 표현을 담고 있는가 (안 불려야 할 때 불리거나, 불려야 할 때 안 불린 사례)
- [ ] 스킬끼리, 또는 AGENTS.md와 스킬이 서로 모순되는가
- [ ] 오래되었거나 아무도 안 쓰는 규칙, 너무 길어진 파일(300줄+)
- [ ] 반복적으로 손으로 하는 단계 → 스크립트나 새 스킬 후보
- [ ] 위험도 대비 자동화 수준이 맞는가 (너무 묶여 있거나, 너무 풀려 있거나)
- [ ] INSTRUCTIONS.md의 지시 중 아직 반영 안 된 것

출력 형식
```
개선 제안 (효과 큰 순, 최대 5개)
1. [대상 파일] 문제 — 근거(LESSONS 항목/사례) — 제안 수정(바꿀 문장 diff) — 효과/위험
반영할까요? (번호 선택 / 전부 / 보류)
```

## B. 자가 업데이트 (사용자가 승인한 항목만)
1. 승인된 수정만 파일에 반영한다. 관련 없는 부분은 건드리지 않는다.
2. `VERSION`을 올린다: 규칙 문구 수정 = patch, 스킬/에이전트 추가·절차 변경 = minor, 구조 변경 = major.
3. `CHANGELOG.md`에 `- [파일] 변경 (이유)`를 남긴다.
4. 반영된 LESSONS 항목은 "승격됨 → <파일>"으로 표시한다.
5. 수정한 스킬은 `work-reviewer`로 검토하거나 eval-rubric 테스트를 1회 이상 돌려 본다.
6. 설치된 사본(`~/.claude/skills` 등)이 따로 있으면 `scripts/install.sh`로 다시 설치하라고 안내한다. claude.ai용이면 `scripts/package.sh`로 zip을 다시 만들고 재업로드를 안내한다.

## C. 원본 저장소에서 최신 버전 받기
- 키트가 git 저장소에 있으면 `scripts/update.sh`를 실행한다 (pull → 변경 요약 → 재설치).
- 로컬에서 고친 내용이 있으면 덮어쓰기 전에 사용자에게 알리고 확인받는다.

## 자동 제안 규칙 (요청이 없어도)
- 큰 작업을 끝냈을 때, 시스템을 고치면 다음에 더 나아질 점이 분명하면 보고 끝에 **한 줄로만** 제안한다: `💡 개선 제안: ... (self-improve로 반영 가능)`.
- 근거 없는 제안, 매번 반복되는 제안은 하지 않는다. 사용자가 거절한 제안은 LESSONS.md에 "거절됨"으로 남기고 다시 꺼내지 않는다.

## 하지 말 것
- 승인 없이 스킬·지침 파일을 고치지 않는다 (LESSONS.md에 관찰을 추가하는 것은 예외).
- INSTRUCTIONS.md의 지시를 개선이라는 이유로 바꾸거나 지우지 않는다. 바꿔야 한다고 보면 사용자에게 묻는다.
