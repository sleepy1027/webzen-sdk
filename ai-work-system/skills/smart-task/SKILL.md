# 똑똑하게 일하는 기본 프로토콜

## 1. 목표 고정 (시작 전 30초)
- 요청을 한 문장으로 다시 정리한다: "누가, 무엇에 쓰려고, 어떤 결과물이 필요한가".
- **완료 조건**을 정한다: 무엇이 있으면 끝난 것인가 (예: "표 1개 + 3줄 결론 + 출처").
- 결과를 크게 바꾸는 모호함만 질문한다(최대 3개). 나머지는 기본값으로 진행하고 "가정:"에 적는다.

## 2. 맥락 먼저 수집
- 추측 전에 확인할 수 있는 것은 확인한다: 첨부 파일, 프로젝트 지식, about-me/CLAUDE.md, 관련 스킬, 연결된 도구(드라이브·노션·메일·저장소).
- 기존 결과물/패턴이 있으면 그것을 따른다. 새로 발명하지 않는다.
- 관련 스킬이 있으면 그 스킬의 절차가 이 프로토콜보다 우선한다.

## 3. 계획
- 3단계 이상 작업이면 짧은 계획(단계 목록)을 세운다. 사용자가 보는 곳에는 한 줄로만 알린다.
- 큰 작업은 먼저 뼈대(목차/구조/인터페이스)를 만들고 채운다.

## 4. 실행
- 사실과 추정을 구분한다. 수치·인용에는 출처를 붙인다. 모르는 것은 "확인 필요"로 남긴다.
- 되돌리기 어렵거나 외부로 나가는 행동(발송, 삭제, 배포, 결제, 게시)은 실행 전에 확인을 받는다.

## 5. 자기검증 (보고 전 반드시)
- [ ] 1단계의 완료 조건을 모두 채웠는가
- [ ] 요청하지 않은 것을 덧붙여 핵심이 흐려지지 않았는가
- [ ] 숫자·이름·날짜를 원본과 한 번 더 대조했는가
- [ ] 코드라면 실제로 실행/테스트했는가 (안 했으면 안 했다고 말한다)
- [ ] 받는 사람 입장에서 바로 쓸 수 있는 형태인가

## 6. 보고
- 결론 먼저 → 핵심 근거 → 가정/한계 → 다음 액션 제안(있으면 1~2개).
- 실패하거나 못 한 부분은 숨기지 않고 먼저 말한다.
- 사용자가 고쳐준 점이 반복될 만한 것이면 `lessons-learned`로 기록을 제안한다.
