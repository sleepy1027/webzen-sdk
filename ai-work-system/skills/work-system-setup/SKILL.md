# AI 업무 시스템 4단계 구축

목표: 매번 프롬프트를 새로 쓰는 대신, **컨텍스트 + 절차(스킬) + 검증 기준**을 파일로 남겨서
어느 Claude(claude.ai, Claude Code, Cowork, API)에 붙여도 같은 품질로 일하게 만든다.

진행 원칙
- 한 번에 4단계를 다 끝내려 하지 말고, 사용자가 지금 있는 단계부터 시작한다. 먼저 "지금 어떤 파일이 이미 있는지"(about-me, 지침, 기존 스킬)를 확인한다.
- 각 단계 산출물은 **파일**로 남긴다. 대화에만 있는 결과물은 시스템이 아니다.
- 사용자가 직접 답해야 하는 것(직무, 선호, 금지사항)은 추측하지 말고 짧게 묻는다. 한 번에 질문은 최대 5개.

---

## 1단계: 컨텍스트 — "나를 아는 AI"

AI가 매번 처음 보는 사람처럼 일하는 이유는 맥락이 없어서다. `templates/about-me.md`를 채워 만든다.

담을 것
- 역할·팀·주요 이해관계자, 쓰는 도구/시스템
- 결과물 기본 형식(언어, 톤, 길이, 표/불릿 선호, 보고 구조)
- **하지 말 것** 목록 (예: 근거 없는 수치, 과한 수식어, 확인 없이 외부 발송)
- 모를 때의 행동: 추측 금지 → 질문 또는 "가정:"으로 명시
- 자주 쓰는 용어집(사내 약어, 제품명)

붙이는 곳
- claude.ai: 설정 → 프로필(개인 선호) 또는 프로젝트 지침 + 프로젝트 지식에 파일 업로드
- Claude Code: `~/.claude/CLAUDE.md`(전역) 또는 저장소 `CLAUDE.md`
- API: system prompt 앞부분

## 2단계: 업무 수집·분해 — "무엇을 맡길지"

1. 사용자에게 최근 1주일 업무를 나열하게 한다(캘린더·메일·메신저·커밋 로그가 연결돼 있으면 그걸로 초안을 만든다).
2. `templates/task-inventory.md` 표로 정리: 업무 / 빈도 / 소요시간 / 입력 / 산출물 / 판단이 필요한 지점 / 위험도.
3. **빈도×소요시간이 크고 위험도가 낮은 것**부터 우선순위를 매긴다. 상위 1~3개만 다음 단계로.
4. 선택한 업무를 단계별 행동으로 쪼갠다: 입력 → 처리 단계 → 판단 기준 → 산출물 → 최종 확인자.
   - "사람이라면 이걸 신입에게 어떻게 가르칠까?"를 기준으로 쓴다.
   - 사용자가 잘된 과거 결과물(예시)을 갖고 있으면 반드시 받아둔다. 예시 1개가 설명 10줄보다 낫다.

## 3단계: 스킬화 — "절차를 파일로"

`templates/SKILL.template.md`를 복사해 업무 하나당 스킬 하나를 만든다.

좋은 스킬의 조건
- `description`에 **언제 쓰는지 + 트리거 표현**을 구체적으로 쓴다(이게 자동 호출 정확도를 결정한다).
- 본문은 "왜"를 함께 쓴다. 규칙만 있으면 예외 상황에서 틀린다.
- 단계는 번호로, 판단 기준은 체크리스트로, 산출물은 형식 예시로.
- 길어지면(대략 300줄+) 세부 자료는 같은 폴더의 `reference/*.md`로 빼고 본문에서 "필요할 때 읽어라"고 링크한다.
- 반복 계산·변환은 스크립트(`scripts/`)로 넣고 스킬에서 호출하게 한다.
- 마지막에 **완료 전 자기검증 체크리스트**를 둔다.

## 4단계: 검증·자동화 — "믿고 맡기기"

1. 평가 기준표(`templates/eval-rubric.md`)를 만든다: 항목별 1~5점 + 통과선.
2. 같은 입력/서로 다른 입력으로 **5~10회** 돌려서 점수를 기록한다. 평균과 최저점을 본다(최저점이 실제 리스크다).
3. 실패 패턴을 스킬 본문에 반영한다(→ `lessons-learned` 스킬 사용). 다시 돌린다.
4. 통과선을 안정적으로 넘으면 자동화 단계를 정한다:
   - 위험 낮음(내부 요약, 초안): 스케줄 실행/자동 실행 허용
   - 위험 중간(사내 공유): AI 초안 → 사람 검토 후 발송
   - 위험 높음(고객·외부·돈·삭제): 항상 사람 승인
5. 커넥터(메일·캘린더·드라이브·노션·GitHub 등)는 스킬이 실제로 필요한 것만 연결한다.
